## Probe Experiments

The helper `tools/run_pv26_lane60_probe.py` runs a derived phase-4 probe from an existing run. It disables det/tl loss, keeps the lane-family sampler focused on lane/stop-line/crosswalk positives, and avoids heavy step-history/checkpoint spam.

### upper_trunk_rebalance

Settings:

- `freeze_policy=lane_family_plus_upper_trunk`
- `trunk_lr=2e-6`
- `head_lr=1e-4`
- loss weights: lane `1.25`, stop-line `2.0`, crosswalk `1.5`
- 3 epochs, 512 train batches/epoch, 128 val batches/epoch

Training-val summary:

| Epoch | Objective | Lane F1 | Stop-line F1 | Crosswalk F1 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 0.5000 | 0.3600 | 0.1583 | 0.5148 |
| 2 | 0.5301 | 0.3601 | 0.4082 | 0.4303 |
| 3 | 0.5271 | 0.3636 | 0.4000 | 0.4573 |

The run slightly exceeded the original objective on the same trainer summary, mostly by lifting stop-line. The separate threshold sweep did not confirm a broad improvement.

### heads_rebalance

Settings:

- `freeze_policy=lane_family_heads_only`
- `trunk_lr=0`
- `head_lr=1e-4`
- same loss weights as `upper_trunk_rebalance`
- 2 epochs, 512 train batches/epoch, 128 val batches/epoch

Training-val summary:

| Epoch | Objective | Lane F1 | Stop-line F1 | Crosswalk F1 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 0.5013 | 0.3624 | 0.1560 | 0.5148 |
| 2 | 0.5319 | 0.3695 | 0.4000 | 0.4190 |

This was slightly better than upper-trunk on the trainer's phase objective, with less trainable surface. But the val128 threshold sweep again landed near the same mean-F1 band as the source checkpoint.

## Decision

This pass did not find a credible 60% path.

What it falsified:

- Threshold calibration alone is not enough.
- A small upper-trunk unfreeze is not clearly better than heads-only rebalance.
- Short loss rebalance can make stop-line look better in the trainer summary, but the gain is not robust under the separate val128 threshold sweep.

Current best interpretation:

- The checkpoint is not simply under-thresholded.
- The phase-4 objective can be nudged by task tradeoffs, but lane remains around 0.36-0.40 F1 and stop-line is still unstable.
- Another 4-day run with only small LR/loss-weight tweaks is unlikely to jump to 60%.

Recommended next gate:

1. Run full-val threshold/export analysis for the source checkpoint and the heads-only probe if a stronger selection decision is needed.
2. Treat `heads_rebalance` as the cheaper follow-up if doing one more short resume.
3. Do not promote `lane_family_plus_upper_trunk` as default without full-val evidence.
4. For a real 60% attempt, shift the next architecture work toward target/decoder/sampler evidence for lane and stop-line, not just longer training.
